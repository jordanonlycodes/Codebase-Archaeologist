      TRANSPARENT BY DESIGN

      Know what’s being measured.

      Repository metrics describe structure. Optional C-function predictions identify defect-related patterns for manual review; they do not confirm vulnerabilities.

      What’s included and excluded?

      UTF-8 text files are scanned recursively. Git internals, dependencies, virtual environments, caches, build outputs, binaries and nested archives are excluded. Empty included directories count; the temporary extraction root does not. ZIP wrapper folders are retained.

      Excluded file counts will appear after analysis.

      How are lines counted?

      Total lines are physical text lines, including blanks. Source lines include only recognized source languages, including their blanks and comments. Comment-only lines are measured using Python tokens; inline comments and docstrings remain code. Standard JSON has no comments. Other languages show unavailable counts, not zero.

      How is the upload handled?

      ZIP files are checked for unsafe paths, links, conflicting entries, excessive expansion and unsupported compression. Limits: 25 MiB uploaded, 100 MiB expanded, 2 MiB per entry, 5,000 entries, 30 path levels and a 200:1 compression ratio. Uploaded code is never executed. Temporary files are deleted after success or failure; results remain in this browser tab until replaced or refreshed.
